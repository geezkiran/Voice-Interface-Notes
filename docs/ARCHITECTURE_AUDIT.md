## 1. How the Xcode project references files

**Classic groups (`PBXGroup` + explicit `PBXFileReference`), but the file is generated
output.**

```
$ grep -c PBXFileSystemSynchronizedRootGroup ReminderApp.xcodeproj/project.pbxproj
0
$ grep -n "objectVersion" ReminderApp.xcodeproj/project.pbxproj
6:  objectVersion = 77;
```

```
/* Begin PBXGroup section */
    85A2FE815E0BAD37265162F4 = {
        isa = PBXGroup;
        children = (
            DFCB3BCF244590EF1642DC91 /* App */,
            BE28F8160E1B855F9A1ED79E /* Packages */,
            D45D05BCF2869004F1A7455A /* Reminder App */,
            6E0D47D90EE552A512B67A6B /* Products */,
        );
```

Despite `objectVersion = 77` (Xcode 16+), there is not a single synchronized root group —
XcodeGen emits classic groups. The practical consequence for Phase 2 is the **opposite**
of the brief's assumption: `project.pbxproj` must never be hand-edited, because it is
regenerated from `project.yml`. Any hand edit is silently destroyed on the next
`xcodegen generate`. `project.yml` itself has a comment recording exactly this trap
("These four were only ever set in the generated .pbxproj, which meant regenerating the
project silently dropped them").

The app target's entire file membership is three entries:

```
PBXBuildFile: ReminderAppApp.swift in Sources
PBXBuildFile: Assets.xcassets in Resources
PBXBuildFile: ReminderApp in Frameworks   ← the SPM product
```

Everything else in the app is compiled by SwiftPM, where membership is determined by
directory position under `Sources/<TargetName>/`. **Moving a Swift file across a
`Sources/<Target>/` boundary changes its module; moving it within one is free.**

## 6. Risk list — what breaks on a move

| Risk | Location | Why it matters |
|---|---|---|
| **Module boundary = directory** | `DesignSystem/Sources/<Target>/` | Moving a file between `DesignSystem/`, `ReminderApp/`, `DesignSystemDemo/` changes its module. That forces `import`/`public` churn — allowed by rules 1 and 2 only in the narrow case, so Phase 2 must keep every move *inside* one `Sources/<Target>/` tree |
| **`project.pbxproj` is generated** | `ReminderApp.xcodeproj` | Hand edits are destroyed by `xcodegen generate`. All Xcode-side moves go through `project.yml`. The pbxproj diff the brief asks for in Phase 2 is only meaningful as regenerated output |
| **`@main`** | `App/ReminderAppApp.swift:4` | Sole entry point; `project.yml sources: - path: App` means the whole `App/` folder is the target's source root. Moving `App/` requires editing `project.yml` in the same commit |
| **Info.plist path is pinned** | `project.yml: info.path: App/Info.plist` | Moving the plist without updating `project.yml` fails the build |
| **Non-Apple Info.plist keys** | `GROQ_API_KEY`, `DEEPGRAM_API_KEY` | Read at runtime via `Bundle.main.object(forInfoDictionaryKey:)` — `GroqClient.swift:55`, `DeepgramTranscriptSource.swift:568`. `project.yml` carries a comment explaining that `INFOPLIST_KEY_*` silently drops these, so the real plist must stay |
| **xcconfig path is pinned** | `project.yml: configFiles: Debug/Release: Secrets.xcconfig` | `Secrets.xcconfig` is gitignored and lives at the repo root. Moving it into `Supporting/` breaks the build for anyone who has already copied the example file |
| **Resource lookup by name** | `Avatar.swift:9` `Image("ProfileAvatar", bundle: .module)`; `SerifFont.swift:46` `Bundle.module.url(forResource: "SortsMillGoudy-Regular", …)` | Depends on `Resources/` staying under the `DesignSystem` target, since `.process("Resources")` in `Package.swift` is a relative path |
| **Asset catalog name** | `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` | The catalog must remain in the app target's source root |
| **Scripts assume the package layout** | `run-ios-app.sh:22,35`, `run-ios-preview.sh:22,24` | Both resolve `DS_DIR` as `dirname/..` and build into `$DS_DIR/.build/xcode/...`. Moving `scripts/` out of `DesignSystem/` breaks them silently |
| **`ReminderAppIOSApp.swift` has two `@main`s** | lines 10 and 22 | `#if` guarded. Any move must not disturb the conditional |
| **No entitlements, no localization, no storyboards, no generated code** | — | Confirmed absent: no `.entitlements`, no `.strings`/`.lproj`, no `.storyboard`/`.xib`, no `NSClassFromString` |
| **No test suite to catch regressions** | — | The build is the only gate. Every Phase 2 commit must build, since nothing else will notice a break |

## 7. What the audit contradicts in the brief

1. Deployment target is iOS 26, not iOS 18, and the design system depends on iOS 26-only Liquid Glass APIs.
2. There is no test suite, so there is no test baseline and `Tests/` would be created empty.
3. `project.pbxproj` is generated; the "reflect every move in project.pbxproj" instruction inverts to "reflect every move in `project.yml`".
4. The proposed root-level `App/ Features/ Core/ DesignSystem/` tree cannot be applied at the repo root without dissolving the SPM package. Per your Phase 0 decision, Phase 1 will propose that shape **inside** `DesignSystem/Sources/ReminderApp/`.
5. The codebase is already layered better than the brief anticipates: no view imports SwiftData, no model imports SwiftUI. The restructure is therefore mostly folder naming, not untangling.
